Discrete Logarithm Challenge

Eve holds p = 23, g = 5, and A = 8. To recover Alice's secret a, she must solve for x in: 5x ≡ 8 (mod 23).

Crucial Security Concept: Passive Eavesdropping vs. Active Man-in-the-Middle Passive eavesdropping never automatically exposes the shared secret if proper cryptographic parameters are used; the Discrete Logarithm barrier protects the exchange. However, unauthenticated Diffie-Hellman cannot resist active Man-in-the-Middle attacks because Alice has no way of verifying whether public key B originated from Bob or from Eve!

Academic Toy Parameters

Small Prime (p = 23)

5 Bits • 22 Trials

Because the prime modulus has only 22 possible non-zero remainders, an attacker's laptop can test every candidate exponent in under 1 millisecond. This makes it ideal for educational demonstration, but completely insecure for real-world usage.

Brute-force complexity: O(p) = 22 iterations
Production Standard (TLS 1.3 / SSH)

MODP Group 14 (p ≥ 2048 Bits)

2048 Bits • > 10616 Combinations

Modern protocols use 2048-bit to 4096-bit primes, or 256-bit Elliptic Curves (Curve25519). Even with the best known algorithms (General Number Field Sieve), solving the discrete logarithm would take billions of years utilizing all global supercomputers combined.

GNFS complexity: L_p[1/3, 1.923] ≈ 2^112 operations
Theoretical Defense Guide

Diffie-Hellman Security & MITM Defense

1. Why is Passive Eavesdropping Ineffective Against Production DH?
In classical Diffie-Hellman, the eavesdropper sees \(p\), \(g\), \(A = g^a \bmod p\), and \(B = g^b \bmod p\). Finding \(K = g^{ab} \bmod p\) from \(A\) and \(B\) is called the Computational Diffie-Hellman (CDH) problem, which is believed to be computationally equivalent to the Discrete Logarithm Problem (DLP). When \(p\) is sufficiently large (≥ 2048 bits), no polynomial-time algorithm exists to solve this problem.

2. Why Did Our Simulator Crack the Key?
Our interactive demonstration used \(p = 23\). The search space has only \(p - 1 = 22\) elements. Eve's script simply evaluated \(5^1, 5^2, \dots, 5^6 \equiv 8\) sequentially in a few microseconds.

3. How Does the Man-in-the-Middle (MITM) Attack Work?
Raw Diffie-Hellman provides confidentiality, but lacks mutual authentication. Because packets carry no cryptographic proof of the sender's identity, an adversary in the network routing path can impersonate both ends, establishing two separate keys (\(K_{AE}\) and \(K_{EB}\)) without Alice or Bob knowing.

4. How Do Real-World Protocols Stop MITM?
Production protocols combine Diffie-Hellman with Digital Signatures and Public Key Infrastructure (PKI):

  • TLS 1.3: The server signs its ephemeral public key with an RSA or ECDSA private key certified by a trusted Certificate Authority (CA).
  • Station-to-Station (STS) Protocol: Both parties sign their exchanged keys and verify certificates before computing session keys.
  • SSH: Uses host keys and "Trust On First Use" (TOFU) or SSH certificates to verify the server's public key fingerprint.
